## 0. 执行原则与用户授权边界

用户本轮明确授权（2026-09-20 指令，覆盖旧阶段限制）：

1. **建筑室内空间详细完整化**：至少一个两层（含夹层/通高空间）的房间内部结构，人可以推门进入，内部陈设详细美观，有审美品味，可上楼梯。
2. **原场地面丰富**：街道两侧、广场等增加丰富、详细、美观的设计。
3. **低硬件压力优先**：不同地图分开加载、不必同时在场——房屋内外可以拆成两张地图分别加载（若同时加载确实合适也可，但默认拆分）。
4. **计划先行**：先写成本章，再严格按本章落实；计划与落实都必须有详细的验收方案与真实验收确认。

据此对 `AGENTS.md` 的既有语义作如下**显式修订**（实施时同步写回 AGENTS.md，清理过期表述）：

| 旧语义 | 新语义（本轮起生效） |
| --- | --- |
| 第一阶段"只制作一个生产地图" | 生产地图 = 场景单元：`m01_afterglow`（街区外部）与 `m01_repair_interior`（维修铺室内）为两张**独立加载**的生产地图，稳态仍严格单活动地图 |
| "不实现可进入房间" | `m01_repair_interior` 是完整的可进入室内；其余店铺仍为浅景橱窗 |
| "不做玩家角色/物理行走控制器" | 仍**不引入**物理引擎、CharacterBody、碰撞体与角色形象。"人"= 第一人称**步行观察相机**（重力贴合地面、踏台阶上楼、身体半径阻挡），数据由地图定义驱动，是观察工具的扩展而非玩法系统 |
| 禁止交互物体 | 唯一新增交互是**门户（门 + F 键进入/返回）**，属于场景切换工具操作；不引入物品拾取等玩法 |

继续有效的硬约束：Godot 4.7.2 标准版、Mobile 渲染器、离线运行、严格单活动地图、运行时不烘焙、经济档默认、不靠 Bloom/雾遮丑、生成不覆盖精修、LightmapGI 子树内不放 PackedScene 实例、面片一律走 `mb.quad`（绕序由 `_flush()` 保证）。

诚实边界：本章写作时已审计实际代码（`scripts/`、`tools/`、`addons/neon_bake`、1.1 交接与 review），接口描述与现状对齐；所有"已完成/已验证"状态只能由真实运行与截图确认。

## 1. 最终成果与范围

### 1.1 用户可见成果

1. 站在维修铺门前，门在靠近时开启，提示"进入 余晖维修"；按 F 加载**店内地图**，出生在门内侧。
2. 店内为一层工坊 + 通高中庭 + 内楼梯 + 二层居家阁楼的两层结构；第一人称步行，能沿楼梯走上二层、凭栏俯瞰一层橱窗街景。
3. 店内陈设按"修理铺工坊 + 楼上住家"叙事布置：工作台/工具墙/待修电动摩托/零件架/自动售货机/吊扇……楼上沙发/餐桌窗景/床龛/终端桌/晾衣与绿植；窗外是蓝调黄昏街景小景，不是虚空。
4. 店内按 F（门口）返回街区，落位在维修铺门外。
5. 街区地图的街道两侧与广场新增成组道具（行道树/自行车棚/外摆冰柜/夜宵推车/晾衣/立牌等），近景更丰富，构图不退步。
6. 两张地图均独立烘焙、独立验收；稳态任何时刻只有一张活动地图。

### 1.2 本章不做

- 物理引擎、CharacterBody3D、碰撞形状、导航、跳跃蹲伏、跑酷。
- 可见角色形象/手部模型/第一人称持物动画（无角色系统，沿用观察相机）。
- 其余店铺的完整室内；维修铺外部体量在街区图中保持现状（室内是独立地图，不追求内外网格无缝连续）。
- 多套室内时段光照、动态昼夜、天气。
- 电梯、阳台外挑、三层以上结构。
- 1.1 遗留的 G5/G6（全量性能采样与发布验收）不在本章门槛内，但本章不得使其更难达成。

## 2. 关键决定与理由

| 决定 | 内容 | 理由 |
| --- | --- | --- |
| D1 内外分图 | 室内为独立地图 `m01_repair_interior`，经门户切换 | 用户点名允许分图；严格单活动地图合同零改动即天然满足"低负荷"；室内 lightmap/网格与街区完全隔离，互不增加稳态成本 |
| D2 人=步行相机 | 第一人称步行观察（眼高 1.62m，重力贴合，踏步上楼），无形象无物理 | 满足"人可以推门进入、上楼梯"的体验，同时不违反"无玩家角色/物理"的项目边界；实现是纯数据驱动（AABB 行走面 + 现有禁入 AABB），成本极低 |
| D3 门=接近自动开 + F 确认过门 | 靠近门户半径内门扇 Tween 开启并提示；F 触发地图切换 | "推门进入"的观感（门为你打开、走入），又避免把场景切换做成误触 |
| D4 楼梯=直跑 16 级轴对齐台阶盒 | 每级踏步 0.32m 进深 × 0.197m 抬升 | 与行走面数据（AABB 顶面）天然一致，步行/烘焙/视觉三者同源；不引入斜面 |
| D5 室内叙事 | 一层"近未来修理工坊"、二层"店主居家阁楼"、前部通高中庭承接黄昏窗光 | 延续"雨停后的蓝调时刻"：外冷内暖、下方劳作上方生活、竖向空间做记忆点 |

### 3.5 窗外小景（Backdrop，不烘焙）

前窗/二层窗外 6..12m 范围：人行道条 + 对面店铺立面（2 个体量，带 3..4 扇暖窗）+ 1 盏路灯（暖光池落在人行道）+ 1 辆停泊摩托剪影 + 天空为室内图自己的 ProceduralSky 黄昏。东窗外简化对面山墙。窗玻璃为不透明/近不透明面板，避免透明排序与高成本（与 1.1 手法一致）。

### 3.6 材质与预算

- 复用街区共享材质：`concrete_plain / wall_brick / wall_warm / wood / metal_dark / metal_teal / glass_dark / glass_shop / door_dark / rubber / bulb_warm / lamp_lens / poster` 等。
- 新建（内联于室内场景，不进共享库）：木地板（二层）、地毯（暗赤）、沙发织物、床品（暖）、终端屏（青自发光）、工位划线黄、售货机面板（青）。常规 512/1024，不新建 4K。

### 3.11 动画与音效预算

- 环境动画节点 ≤ 6：吊扇 ×2（rotate）、灯串 flicker ×1、售货机灯带 flicker ×1、终端屏呼吸 ×1、床头灯 flicker ×1（可裁）。
- 粒子：0（店内不设蒸汽；如最终加 1 处需 Balanced 档且不超 2 上限）。
- 音效：可选 1 路店内底噪（默认静音，不阻塞验收）。

## 4. 步行观察模式合同（ObserverCamera 扩展）

### 4.1 数据与接口

`MapDefinition` 新增（schema_version 仍为 2，字段缺省即旧语义，向后兼容）：

```text
@export var camera_mode: String = "fly"        # "fly" | "walk"
@export var walk_surfaces: Array[AABB] = []    # 盒顶面 = 可立足面（XZ 含点判定）
@export var portals: Array[Dictionary] = []    # {pos:Vector3, radius:float,
                                               #  target_map_id:String, target_anchor:String, label:String}
```

`validate()` 增加：camera_mode ∈ {fly, walk}；walk 且非测试图时 walk_surfaces 非空、眼高样本点（每面中心+1.62m）须落在 camera_bounds 内且不进任何禁入盒；portals 各项字段齐全、radius ∈ (0,6]、target 非空。

`MapRoot` 增加 `get_camera_mode() -> String`、`get_walk_surfaces() -> Array[AABB]`（副本）、`get_portals() -> Array`（深拷贝值）；`validate_runtime_contract()` 按上条复检。`MapManager.get_camera_contract()` 返回值增加 `camera_mode / walk_surfaces / portals` 键，并在激活期把两者传入 `ObserverCamera.bind_map_contract(map_id, bounds, exclusions, camera_mode, walk_surfaces)`（后两参带默认值，旧调用不破坏）。

### 4.2 运动规则（walk 模式）

| 项 | 值 | 说明 |
| --- | --- | --- |
| 眼高 | 1.62 m | `_pos.y = feet + 1.62` |
| 步速 | 2.2 m/s；Shift 4.4 m/s | 滚轮仍调 0.5..15 档位倍率 |
| 朝向 | 右键拖动，与 fly 相同 | 俯仰限制 ±80° |
| 水平移动 | WASD 按yaw取水平方向 | **Q/E 无效**（不飞行） |
| 踏步上 | STEP_UP = 0.30 m | 单帧可自动登上 ≤0.30m 的更高地面（楼梯 0.197 ✓） |
| 踏步下 | STEP_DOWN = 0.45 m | 单帧可自动落至 ≤0.45m 更低地面（下楼 ✓） |
| 边缘阻挡 | 拟移动点无满足条件的地面（无地面 / 高差超限）→ 取消该帧水平位移 | 防掉入楼梯井/穿出二层边缘；无坠落模拟 |
| 墙体阻挡 | 复用禁入 AABB 小步检测（EXCLUSION_STEP 0.4 + INFLATE 0.35 身体半径膨胀） | 与 fly 同一份数据 |
| 落点判定 | 对全部 walk_surfaces 取"XZ 含点（外扩 0.12m 脚掌容差）且 top ≤ feet+STEP_UP 的最高 top" | 无物理、O(n) n≤~20 |

实现落在 `camera_controller.gd`：新增 `_walk_mode/_walk_surfaces`、`walk_move(motion: Vector3)`（可被测试直接调用的纯位移函数：水平排斥 + 地面贴合）与 `_process` 分支。锚点/书签位姿照旧走 `apply_pose`；walk 图的锚点 y 必须等于行走面顶 + 1.62（assemble 侧保证）。

### 4.3 walk_surfaces 数据示例（代表格式）

```json
{ "camera_mode": "walk",
  "walk_surfaces": [[0.24,0,-6, 9.76,0.001,12], [3.6,0,-6, 0.32,0.197,1.1], "...16 级...", [3.4,3.15,-4.8, 6.6,0.001,10.8], [8.8,3.15,-6, 1.2,0.001,1.2]] }
```

（六元组 = AABB pos + size；台阶块按踏步实际盒写。）

### 4.4 门户运行时（main.gd + tool_ui）

- `map_loaded` 后缓存当前图 `portals`（值副本）；在 `pose_changed`（≤10Hz）里做距离判定（每图 ≤4 个，开销可忽略）。
- 进入半径：`tool_ui.show_portal_hint("按 F — %s" % label)` 且经 MapRoot `set_portal_door_open(true)` 开门；离开则恢复。门动画由 MapRoot 用 Tween 驱动枢轴节点（组 `portal_door`，meta `swing_deg`），地图卸载即随 Tween 清理。
- 按 F：`map_manager.request_map(target_map_id)`；忙碌/失败仅提示，不重复发。目标图加载后由 MapManager 应用其 `default_anchor` 或门户指定 `target_anchor` —— 扩展 `request_map(map_id, force_reload=false, entry_anchor=&"")`（第三参缺省走默认锚点；签名兼容）。
- 地图菜单仍可直接切换两图（门户是快捷方式，不是唯一入口）。

## 10. 遇到问题时如何继续

| 情况 | 允许 | 不允许 |

| 门户切换偶发 ERR_BUSY | 提示稍后再试；事务语义保持 | 绕过互斥强制双加载 |
